# CLIP 与多模态 Embedding 模型谱系

> 本文是 deltabox 项目的内部 wiki，解释 CLIP 的原理、双塔架构中的「文本塔」概念，
> 以及当前主流多模态 embedding 模型与 CLIP 的关系。
> 模型选型数据见 [[../embedding-models.md]]。

## 什么是 CLIP

**CLIP**（Contrastive Language-Image Pretraining）是 OpenAI 于 2021 年发布的模型
（论文：《Learning Transferable Visual Models From Natural Language Supervision》），
是**多模态 embedding 的鼻祖**。

### 核心思想

用 4 亿对「图片 + 文字描述」做**对比学习**（contrastive learning）：

```
图片编码器 (Image Encoder)  ──→  图片向量
                                        ↘
                                   让配对的图文向量靠近，
                                   不配对的拉远
                                        ↗
文本编码器 (Text Encoder)   ──→  文本向量
```

训练完成后，图片和文本被映射到**同一个向量空间**——语义相近的图文，向量距离就近。于是可以：

- **以文搜图**：输入「一只在图书馆的猫」，找出向量最接近的图片（这正是 deltabox 想要的语义搜索）
- **以图搜文 / 以图搜图**：反向同理
- **零样本分类**：不用针对特定类别训练，直接用文本描述做分类

CLIP 之前，图文检索需要专门训练的分类器；CLIP 之后，
「统一向量空间 + 余弦相似度」成为行业标准范式。

## 双塔架构与「文本塔」

CLIP 由**两个并行的编码器**组成，工程上习惯叫「双塔」（dual-encoder / two-tower）：

```
        图片 ──→ ┌─────────────┐
                 │   视觉塔     │  (Vision Tower)
                 │  图片编码器  │ ──→ 图片向量
                 └─────────────┘
                          同一向量空间
                 ┌─────────────┐
        文本 ──→ │   文本塔     │  (Text Tower)
                 │  文本编码器  │ ──→ 文本向量
                 └─────────────┘
```

- **视觉塔**：通常是 ViT（Vision Transformer），把图片编码成向量
- **文本塔**：一个 Transformer，把文字编码成向量

CLIP 训练时两座塔**联合优化**，让配对的图文向量靠近；推理时两座塔**可以独立使用**——
提前用视觉塔把图库全部编码存好，搜索时只跑文本塔编码查询词，再做向量比对。
这就是双塔架构在检索场景高效的原因。

### 「砍掉文本塔」：纯视觉模型

以 **DINOv2**（Meta）为代表的纯视觉模型只训练了视觉塔：

```
        图片 ──→ ┌─────────────┐
                 │   视觉塔     │ ──→ 图片向量
                 └─────────────┘
                 （没有文本塔）
```

它没有文本编码器，也不做图文对比学习——训练目标是纯视觉的**自监督学习**
（让模型自己从图片里学特征，例如同一张图的不同裁剪视角应产生相近的向量）。

能力对比：

| 能力 | CLIP（双塔） | DINOv2（只有视觉塔） |
|---|---|---|
| 以文搜图：「找一张图书馆的猫」 | ✅ 文本塔把查询编码进同一空间 | ❌ 文字进不了向量空间，无法搜 |
| 以图搜图：「找和这张相似的图」 | ✅ 可以 | ✅ 且更强——全部训练容量都花在视觉特征上 |

## 主流模型与 CLIP 的关系

当前多模态 embedding 模型可按与 CLIP 的关系分为四条演进路线。

### 路线一：CLIP 的直接后代（同架构改进）

| 模型 | 关系 |
|---|---|
| **OpenCLIP** | 开源社区对 CLIP 的复现，开放训练代码和数据（LAION），是后续研究的基础 |
| **MetaCLIP**（Meta） | 架构不变，改进数据清洗策略 |
| **SigLIP / SigLIP 2**（Google） | 把 softmax 对比损失换成 **sigmoid 损失**，训练更高效、效果更好；SigLIP 2 增加多语言、定位能力。目前公认的「CLIP 现代替代默认款」 |
| **JinaCLIP v2** | CLIP 架构现代化 + Matryoshka 维度压缩 + 多语言 |
| **MobileCLIP**（Apple） | CLIP 轻量化，面向手机端 |
| **EVA-CLIP** | 用更强的视觉编码器替换 CLIP 的 ViT |

共同点：**双塔结构 + 对比学习**，与 CLIP 完全同构，只换损失函数、数据或编码器。

### 路线二：从双塔走向统一多模态大模型

| 模型 | 关系 |
|---|---|
| **Jina Embeddings v4** | 不再是独立双塔，基于 VLM（视觉语言模型）做 embedding，文本/图片统一处理，支持 ColBERT 式多向量（late interaction） |
| **Qwen3-VL-Embedding** | 基于 Qwen3-VL 大模型，一个模型处理文本/图片/**视频**，能力远超 CLIP 的图文两模态 |
| **Nomic Embed Multimodal** | 类似思路，基于大模型的多模态 embedding |

这是**范式升级**：CLIP 只能做浅层图文对齐，大模型派生方案理解力更深
（能处理图表、文档版式、跨模态推理）。

### 路线三：多向量 / 文档检索方向

- **ColPali / ColQwen2**：受 ColBERT 启发的**多向量**方案。CLIP 把一张图压成一个向量，
  细节全丢；ColPali 保留 patch 级的多个向量，做视觉文档检索（扫描 PDF、表格截图）
  效果远超 CLIP 类单向量模型。

### 路线四：纯视觉方向

- **DINOv2/v3**（Meta）：砍掉文本塔，只做图片自监督训练。不能做「以文搜图」，
  但**纯视觉相似度**（找长得一样的图）比 CLIP 强。

### 文本 embedding 和 CLIP 的关系

Qwen3-Embedding、BGE-M3、E5 等**文本模型与 CLIP 没有架构关系**——
它们源自 BERT/LLM 这条语言模型路线。但它们**继承了 CLIP 确立的思想**：
对比学习 + 统一向量空间 + 相似度检索，只是应用在纯文本领域。

## 谱系图

```
                    CLIP (2021, OpenAI)
                    图文统一向量空间
                          │
        ┌─────────────────┼──────────────────┐
        │                 │                  │
   双塔改进派         大模型派            多向量派
   OpenCLIP          Jina v4            ColPali
   SigLIP 2 ★        Qwen3-VL-Emb ★     ColQwen2
   JinaCLIP v2       (文本+图+视频)      (文档检索)
   MobileCLIP
        │
   纯视觉派: DINOv2 (砍掉文本塔)
```

★ = 项目调研中推荐给 deltabox 的两款（详见 [[../embedding-models.md]]）。

## 对 deltabox 的意义

CLIP 证明了「个人文件可以用自然语言搜」这条路可行，但 CLIP 本身
（英文为主、77 token 文本上限、单向量）已经过时：

- **自然语言搜图** → 必须用双塔模型：**SigLIP 2**（轻量、多语言）或
  **Qwen3-VL-Embedding**（还覆盖视频）
- **相似图片去重 / 聚类**（如连拍照片挑最优）→ 纯视觉模型 **DINOv2** 反而更好

两者不矛盾，设计上可以并存——`design.md` 中「图片相似度」和「语义检索」
本来就是两个独立需求。
